# PLAN: Исключение нулей («не наблюдал») из расчётов методики

Дата: 2026-07-30

## Шаги

1. **analytics.ts — единая точка правила.** Добавить константу
   `NO_OBSERVATION_SCORE = 0` и хелпер `meaningfulScores(nums)` (фильтр
   `> NO_OBSERVATION_SCORE... точнее !== 0`). Использовать его во всех
   местах, где массивы баллов входят в расчёты (avg, дисперсия, выбросы).
2. **results.service.ts — фильтр на входе.** При сборе perLane (:103),
   respondentMeans (:179) и indicatorScores (:181) пропускать score 0 —
   тогда все производные (средние, ГЭП, итоговая, дисперсия, выбросы,
   промпт) чистые автоматически, без правки каждой формулы.
3. **scaleMin без нуля.** В results.service.ts (:198) и всюду, где min
   шкалы: `Math.min(...values.filter(v => v !== 0))`; легенда шкалы
   (текст «0 — … · 1 — …») остаётся полной.
4. **Фронт: оси диаграмм.** Report360View.tsx:336 и SubjectPanel.tsx:165 —
   min оси из пунктов шкалы без нуля (той же формулой).
5. **Сид: утверждённая шкала 0–4.** В seed-oc360.ts заменить набор
   scalePoints на утверждённый (0 — не могу оценить/не наблюдал … 4 — во
   всех, даже сверхсложных), имя шкалы «Утверждённая 0–4». Идемпотентность
   не трогаем: существующая заполненная шкала не перезаписывается.
6. **Смоуки и проверки.** Node-смоук: avg([0,3,4])==avg([3,4]);
   avg([0,0])==null; порог выбросов при шкале 0–4 равен 2 (min 1 + 1).
   `tsc --noEmit` и build backend+frontend.
7. **Коммит и пуш в mvp2**; в итоговом сообщении — черновики записей
   DECISIONS (0 исключается из расчётов) и напоминание пергенерировать
   отчёты, где в данных были нули.

## Альтернативы

- **Фильтровать только внутри avg()**: отвергнута, потому что не закрывает
  дисперсию, выбросы «низких баллов», средние респондентов и индикаторные
  баллы в промпте — нули продолжили бы искажать разброс и попадать в LLM
  как «низкие оценки», т.е. не устраняет причину.
- **Не хранить нули вовсе (не сохранять ответ 0 в БД)**: отвергнута,
  потому что теряется факт «не наблюдал» (полезен HR для полноты картины
  и для отличия «не ответил» от «не видел»), и задним числом не починит
  уже сохранённые нули.

## Риски

- 🟡 На проде уже есть ответы с 0 → после деплоя средние в закрытых циклах
  изменятся при просмотре (расчёт на лету). Следим: это ожидаемое
  поведение; уже сгенерированные отчёты автоматически не пересчитаются —
  их нужно перегенерировать вручную.
- 🟡 Группа «все нули» станет «—» на диаграммах → проверить, что фронт
  рисует null-группы корректно (тот же путь, что группы без респондентов).
- 🟢 Сид: имя шкалы меняется — на новых установках появится «Утверждённая
  0–4»; старые установки сид не трогает (проверка count > 0 остаётся).
