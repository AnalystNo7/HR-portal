# BRIEF: точность интерпретации отчёта 360 (классификация и отбор кодом)
Дата: 2026-07-20

## Формулировка своими словами
LLM систематически ошибается в классификации зон и отборе компетенций (путает знак Δ,
пропускает позиции, нарушает критерии отбора) — подтверждено разбором полного отчёта
Седлецкого. Нужно забрать у модели все решения «что куда относится» и отдать коду; модели
оставить только интерпретационные тексты. Пустые разделы должны получать абзац-объяснение.

## Контекст
Данные (analytics.ts) уже содержат Δ со знаком по каждой паре — модель получает верные
цифры, но переклассифицирует сама. Ошибки на примере Седлецкого: скрытые возможности
(−2,9/−2,1/−1,5) в «Слепых зонах»; пропущены Лидерство +0,67 (руководитель), −0,67 (коллеги),
консенсусы; Системное мышление (окружение 4,25) не в сильных сторонах, но в «зонах развития».

## Критерии успеха
- [ ] Смоук buildAnalytics на цифрах Седлецкого: blindSpotsList пуст; hiddenPotentialList =
      Системное/Стратегическое/Гибкость/Открытый диалог; strengthsTop = Системное, Решение
      проблем, Отв. за результат; developmentAreas = Проактивность; zoneByGroup — по знакам.
- [ ] Техническая часть промпта запрещает модели переклассификацию и требует все компетенции
      в разборах пар; схема содержит emptyReasons.
- [ ] UI показывает абзац-объяснение вместо «Не выявлены» при пустом разделе; HR может его
      править.
- [ ] tsc оба пакета, next build — чисто.

## Открытые вопросы
Все закрыты пользователем: зоны/отбор — кодом; сильные — топ-3 по окружению; зоны развития —
строго ниже целевого; пары — все компетенции; пустые разделы — абзац от модели.
