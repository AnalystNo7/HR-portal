# План: новые диаграммы пар внешних групп + постраничные выгрузки + docx

## Контекст

По примеру нового отчёта (360_new.docx, содержимое согласовано в чате):
1) в веб-отчёт добавляются «Диаграмма сравнения оценок руководителя и подчинённых»
и «…руководителя и коллег» с ИИ-разборами (трактовка Δ и разброса + «Действия»
списком) после всех существующих диаграмм; 2) печать/PDF становится постраничной
со стартовым листом-картинкой; 3) у HR появляется «Скачать DOCX» (фронтенд-
генерация). Решения пользователя: порог включения компетенций |Δ| ≥ 0,4;
«Экстремальные оценки» — следующая итерация; сотруднику только PDF; пустой разбор —
статичная надпись «Значимых расхождений между оценками групп не выявлено»; старые
отчёты показывают диаграммы сразу, разборы — после перегенерации; зависимость
docx (MIT) одобрена; стартовый лист строго как в примере (заголовок, ФИО,
картинка); имя docx = как у PDF; рекомендации по настройке пресетов не нужны.

## Этапы (коммиты в mvp2 поэтапно)

### Этап 1. Backend: раздел externalComparison
- `analytics.ts`: в ReportSelection — `externalPairs`: для пар MANAGER–SUBORDINATE
  и MANAGER–PEER компетенции с |Δ| ≥ 0,4 (Δ = руководитель − группа, по округлению
  до 0,1, сортировка по |Δ| убыв.): { name, managerAvg, groupAvg, delta }.
  Данные средних/разбросов уже есть (byGroup, groupPairs).
- `report.types.ts`: Report360Sections += `externalComparison: ReportExternalPair[]`
  (pair: 'MANAGER_SUBORDINATE' | 'MANAGER_PEER'; items: { competency, managerScore,
  groupScore, delta, text, actions: string[] }); normalizeSections; ALL_BLOCK_KEYS +=
  chart:MANAGER_SUBORDINATE, chart:MANAGER_PEER, extpair:MANAGER_SUBORDINATE,
  extpair:MANAGER_PEER.
- `report.prompt.ts`: фрагмент схемы externalComparison (text + actions 2–3 пункта);
  ALL_SECTION_KEYS; partsForCount: 2 части → externalComparison во вторую;
  3 части → [разделы] / [groupComparison] / [externalComparison, recommendations];
  правила в TECHNICAL_RULES (состав строго из selection.externalPairs, трактовка
  Δ и разброса группы, «Действия» списком) и DEFAULT_METHODOLOGY (по разделам
  методики «Интерпретация по группам респондентов»).

### Этап 2. Frontend: веб-блоки
- `lib/api.ts`: зеркальные типы.
- `Report360View.tsx`: после пар самооценки — 2 блока: ChartBlock (серии
  руководитель+подчинённые / руководитель+коллеги, заголовки как в примере,
  крестик, авто-скрытие при 0 назначенных респондентов группы) + новый
  ExternalPairFindings: просмотр «Компетенция (руководитель X | подчинённые Y)» →
  текст → «Действия:» маркированным списком; редактирование: текст + пункты
  действий (добавить/удалить), карандаш/крестик как у всех блоков; пустой разбор —
  статичная надпись. BLOCK_TITLE для новых ключей.

### Этап 3. Печать/PDF постранично + стартовый лист
- Картинка от пользователя → `frontend/public/report-cover.png` (взять из чата/
  uploads; если файла нет — запросить повторно).
- Стартовый лист (print-only блок): «Результаты оценки 360», ФИО, картинка —
  первой страницей: больше ничего.
- Print-CSS: разрывы страниц по согласованной схеме: титул / интро+шкала /
  сводная таблица / открытые ответы (одним листом) / общая диаграмма /
  сильные+развитие / слепые+скрытые / каждая пара (диаграмма+разбор) /
  рекомендации. Работает и у сотрудника (общий Report360View).

### Этап 4. Выгрузка DOCX (только HR)
- Зависимость `docx` в frontend/package.json.
- `reportDocx.ts`: сборка документа из тех же данных, что рендер (правки HR
  включены); диаграммы: сериализация отрисованных SVG → canvas → PNG → ImageRun;
  постраничность PageBreak по той же схеме листов; сводная таблица таблицей docx;
  титульный лист с картинкой.
- Кнопка «Скачать DOCX» в ReportView (вкладка «Отчёт», рядом с печатью);
  имя файла — как у PDF (ФИО_Результаты_оценки_360.docx).

### Этап 5. Процесс и проверки
- tasks/report-export/BRIEF.md + PLAN.md.
- Смоуки: analytics (externalPairs: порог 0,4 по округлению, сортировка, пары без
  оценок группы отсутствуют); normalizeSections (новый раздел, повреждённые данные);
  partsForCount (новые составы частей); промпт (фрагмент схемы, правила).
- tsc оба пакета, next build (docx-утилита использует браузерные API — смоук
  структуры документа со стабом картинок).
- Коммиты в mvp2 поэтапно, пуш; записи в журналы.
- Приёмка: перегенерация → новые разборы; старый отчёт → диаграммы видны, разбор
  пуст; печать → постранично с титулом; «Скачать DOCX» → файл идентичной структуры.

## Границы
- БД не меняется (новый раздел внутри JSON sections).
- «Экстремальные оценки подчинённых» — не в этой итерации.
- Настройки пресетов (части/лимиты/таймауты) пользователь подбирает сам.
