# BRIEF: блокировка действий над отчётом 360 в статусе «Готов к публикации»
Дата: 2026-07-19

## Формулировка своими словами
Когда HR нажимает «Отметить готовым» (отчёт переходит в статус READY «Готов к публикации»),
отчёт должен стать неизменяемым: кнопки «AI генерация отчета» и «Сброс» — неактивными,
поблочное редактирование (карандаш/крестик) — недоступным. Готовый отчёт нельзя случайно
перегенерировать, откатить или поправить. Разблокировка — кнопка «Вернуть в черновик».

## Контекст
Вкладка «Отчёт» HR-панели: `frontend/app/hr-eval360/[cycleId]/ReportView.tsx` (кнопки,
статусы DRAFT/READY) + `frontend/components/eval360/Report360View.tsx` (проп `editable`
уже управляет карандашами/крестиками — при печати он уже выключается). Backend:
`report.service.ts` — generate/reset/update. Сотрудник видит отчёт только в READY —
его сторона не меняется.

## Критерии успеха
- [ ] При статусе READY кнопки «AI генерация отчета» и «Сброс» видны, но неактивны,
      с подсказкой «Отчёт готов к публикации — верните в черновик для изменений».
- [ ] При READY нет карандашей/крестиков на блоках (отчёт read-only).
- [ ] «Вернуть в черновик» возвращает все возможности.
- [ ] Сервер отклоняет generate/reset (и правку sections) для отчёта в READY
      с понятной ошибкой — защита от устаревшей вкладки/гонки двух HR.
- [ ] tsc (оба пакета) и next build проходят.

## Открытые вопросы
- Триггер = статус READY? — отвечено: да.
- Скрыть или задизейблить? — отвечено: неактивные + подсказка.
- Блокировать ли редактирование блоков? — отвечено: да, полностью read-only.
- Только UI или + сервер? — отвечено: UI + сервер.
