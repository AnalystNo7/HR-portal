# PLAN: правила методики v1.2 — категории и константный целевой уровень

Дата: 2026-07-23

## Шаги

1. `backend/src/oc360/results/analytics.ts`:
   - константы DEV_THRESHOLD = 3.0, STRONG_THRESHOLD = 3.4 (рядом с DEFAULT_TARGET_LEVEL);
   - selection: strengthsTop → strengths: eligible с total != null и total > 3.4
     (по убыванию total, поле { name, total }); developmentAreas: eligible с
     total < 3.0 (по возрастанию, { name, total }); eligible — как в задаче №45.
2. `backend/src/oc360/results/results.service.ts`: targetLevel всегда
   DEFAULT_TARGET_LEVEL (сохранённые cycle.targetLevel игнорируются) — и в
   computeResults, и в выдаче для HR.
3. `backend/src/oc360/report/report.prompt.ts`:
   - DEFAULT_METHODOLOGY: правило категорий v1.2 (|Δ| ≥ 0,6 → только слепые/скрытые;
     иначе по итоговой средней: > 3,4 сильная, < 3,0 развитие, 3,0–3,4 — не входит
     никуда; разделы не пересекаются);
   - TECHNICAL_RULES: selection.strengths / selection.developmentAreas (вместо
     strengthsTop), формулировки про итоговую среднюю.
4. Frontend:
   - `[cycleId]/page.tsx`: удалить поле «Целевой уровень…» из формы редактирования
     цикла (state, валидация, input; update360Cycle без targetLevel);
   - `Report360View.tsx` + `reportDocx.ts`: подзаголовок «по итогу средней оценки»
     у «Сильных сторон» и «Зон развития» (слепые/скрытые — без изменений).
5. Смоуки: пороги строгие (2.99→развитие, 3.0→никуда, 3.4→никуда, 3.45→сильная);
   зонная компетенция (Δ≥0,6) с total 4.2 — только в скрытых; cycle.targetLevel=4.0
   игнорируется (всё считается от 3.0); промпт содержит новое правило.
6. tsc оба пакета, next build; коммит в mvp2, пуш; записи в журналы.

## Альтернативы

- Привязать пороги к настраиваемому целевому уровню (target и target+0,4):
  отвергнута пользователем — уровень зашит в методике, константа; настройка удаляется.
- Оставить топ-3 как минимум при пустых сильных: отвергнута — v1.2 задаёт строгий
  порог, пустой раздел объясняет emptyReasons.

## Риски

- 🟡 У существующих отчётов составы разделов изменятся только после перегенерации —
  ожидаемо, пользователь перегенерирует сам.
- 🟡 Кастомный промт HR (если сохранён) со старой формулировкой топ-3 — рекомендовать
  «Сбросить к стандартному» после деплоя; техчасть всё равно принудит составы.
- 🟢 БД не меняется (колонка target_level остаётся, но не читается).
