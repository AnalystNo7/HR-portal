# BRIEF: Минимальный набор полей сотрудника + подтверждение при пропусках

Дата: 2026-08-04

## Формулировка своими словами

Сейчас сотрудника нельзя завести без пяти полей (табельный, фамилия+имя,
email, должность, подразделение): импорт молча отбрасывает такие строки,
ручная форма падает на сервере. Нужно: обязательный минимум — табельный,
фамилия, имя, email (имя добавлено ответом человека: нужно для обращений
в отчётах 360); должность, подразделение и прочее — опциональны. При
импорте и при ручном сохранении с пустыми опциональными полями — явное
окно «не заполнено: … — продолжить?», а не молчаливый пропуск.

## Контекст

- Импорт: backend/src/import/import.service.ts (parseExcel :96–105 — все
  5 полей жёстко обязательны; executeImport :140 — строки с errors
  отбрасываются). UI импорта уже двухшаговый: предпросмотр → «Импортировать».
- Ручная форма: frontend/app/admin/employees/page.tsx (handleSave — без
  проверок), CreateEmployeeDto в employees.controller.ts — без валидации.
- Схема: Employee.positionId/departmentId NOT NULL (schema.prisma:63–66) —
  требуется миграция (ослабление NOT NULL, аддитивно, CON-003 соблюдён).
- Фронт уже null-безопасен (`position?.name ?? ''`); на бэкенде небезопасные
  обращения: cycle.service.ts:62 (+ проверить report.service/report.prompt,
  profile.service).
- Keycloak не затронут: логин = email, пароль = табельный — оба в минимуме.
- Закрывает открытый вопрос UR-008 («строки Excel без email падают»):
  без email — осознанный отказ строке (email = логин Keycloak).

## Решения человека (2026-08-04)

- Минимум: фамилия + имя + почта + табельный.
- Пустые должность/подразделение — честный NULL (миграция), в UI «—»;
  заглушка «Не указано» отвергнута.
- Импорт-обновление существующего: пустое поле в файле НЕ затирает
  значение в базе.
- Подсказка — модальное окно подтверждения и в импорте (сводка по строкам),
  и в ручной форме.

## Критерии успеха

- [ ] Импорт: строка с минимумом полей импортируется; пропуски должности/
      подразделения помечаются в предпросмотре и попадают в сводку окна
      подтверждения; строки без минимума — в ошибки (как раньше).
- [ ] Импорт-обновление: пустые опциональные поля файла не затирают базу.
- [ ] Ручная форма: обязательные поля помечены, без них сохранение
      блокируется; с пустыми опциональными — окно «не заполнено: … —
      продолжить?»; сотрудник сохраняется с NULL должностью/подразделением.
- [ ] Сервер отклоняет создание без минимума (не полагаясь на UI).
- [ ] Все экраны показывают «—» при пустых должности/подразделении, ничего
      не падает (tsc/build оба, смоук parseExcel).
