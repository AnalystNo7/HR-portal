# PLAN: Обратные вопросы 360 (методика v1.3)

## Шаги (все проверяемые)
1. Схема: `isReverse` в IndicatorTemplate + Cycle360Indicator (аддитивно) → tsc.
2. `invertScore(score, scaleValues)` в analytics.ts: 0→0, иначе (min+max)−score
   по содержательным пунктам → смоук: шкала 0–4 (1→4, 2→3, 3→2, 4→1, 0→0), шкала 1–5 (2→4).
3. respondent.service: инверсия при записи (submit) и деинверсия при чтении
   (getForm) → критерий «черновик показывает нажатое».
4. template/cycle services: флаг в DTO, клоне версии, снапшоте цикла.
5. import-template-v4: флаги в данных (последние 3 — обратные) + синхронизация
   уже залитой версии → интеграционный смоук на локальном Postgres (создание,
   повторный прогон, 9×3 обратных).
6. Фронт: чекбокс «обратный» в редакторе шаблона, бейдж в просмотре → build.

## Отвергнутая альтернатива
Хранить сырые ответы, инвертировать при чтении: каждая точка чтения score
(две агрегации, выбросы, экспорт, будущий код) обязана знать про инверсию —
риск рассинхрона; «структуру отчёта не менять» потребовало бы правок по всей
аналитике вместо нуля правок. Минус выбранного пути — в БД расчётный балл,
а не сырой; принят, т.к. флаг фиксируется снапшотом цикла и не меняется.
