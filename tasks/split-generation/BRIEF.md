# BRIEF: генерация отчёта по частям (1/2/3 запроса)
Дата: 2026-07-21

## Формулировка своими словами
Отчёт целиком (~15К токенов) упирается в потолок вывода Gonka (16384), особенно у
reasoning-моделей — размышления едят тот же бюджет. Пользователь хочет работать на
MiniMax (быстрее) и получать полный отчёт. Нужно уметь разбивать генерацию на 2–3
независимых запроса (каждому — свой лимит вывода) и склеивать результат в один
sections; число запросов настраивается админом в пресете LLM.

## Контекст
- Один вызов completeJson возвращает весь Report360Sections; Kimi выдал 14954/16384 —
  впритык; без явного max_tokens Gonka режет до 3072.
- В llm_settings уже есть maxTokens; пресеты редактируются в /admin/llm.
- Автоповтор при таймауте — на уровне клиента (каждая часть повторяется сама).
- nginx 700s: параллельный запуск частей укладывается, последовательный — нет.

## Критерии успеха
- [ ] В пресете LLM выбор «Одним запросом / 2 запроса / 3 запроса», по умолчанию 1
- [ ] 2/3 части запускаются параллельно, каждая со схемой только своих разделов
- [ ] Ответы склеиваются в целый sections (из каждой части — только её ключи)
- [ ] Ошибка любой части = ошибка всей генерации
- [ ] parts=1 — поведение в точности как раньше; «Технический промт» в UI не меняется

## Открытые вопросы
- Разбивка 2 или 3 — отвечено: выбор в интерфейсе, в пресете LLM.
- Параллельно/последовательно — отвечено: параллельно.
- Ошибка части — отвечено: ошибка всей генерации.
- Дефолт — отвечено: одним запросом (как сейчас).
