## 2026-07-19 — Удаление диаграмм и авто-скрытие пары без респондентов
- Решение: диаграммы сравнения удаляются тем же механизмом hiddenBlocks (ключи chart:SELF_*); пара (диаграмма + разбор) авто-скрывается для всех, если у сотрудника 0 назначенных респондентов группы (по res.progress.total).
- Почему: единый механизм с текстовыми блоками (сбросы восстанавливают автоматически); авто-скрытие по числу назначенных точно отражает «нет группы» (напр. нет подчинённых).
- Затронуто: report.types.ts (ALL_BLOCK_KEYS), frontend Report360View.tsx

## 2026-07-19 — Пресеты LLM в той же таблице llm_settings (+name, +is_active)
- Решение: несколько именованных строк в существующей таблице, а не отдельная таблица; активен ровно один (переключение транзакцией); легаси id="default" — первый пресет («Основная», ленивый бэкфилл).
- Почему: аддитивная миграция; данные текущей настройки переносить не нужно.
- Затронуто: schema.prisma, llm.config.ts, src/settings/, frontend /admin/llm, Sidebar

## 2026-07-19 — Завершённые запуски удаляет только admin
- Решение: корзинка у CLOSED-запусков видна только администратору; усиленное подтверждение вводом названия запуска; сервер дублирует проверку ролей (ForbiddenException).
- Почему: удаление результатов целого цикла невосстановимо; UI-скрытие без серверной проверки обходится прямым запросом.
- Затронуто: cycle.service.ts, cycle.controller.ts, hr-eval360/page.tsx (CyclesTab)

## 2026-07-19 — Конвенции усреднения подтверждены аудитом
- Решение: «Итоговая (средняя)» = среднее групповых средних (включая самооценку, равный вес групп); ГЭП = самооценка − среднее всех баллов окружения (каждый балл равный вес). Оставлены как есть.
- Почему: сверка с методикой по запросу HR; альтернативы (среднее трёх групп для ГЭП, среднее всех баллов для итоговой) отклонены как не соответствующие методике.
- Затронуто: без правок (подтверждение results.service.ts / analytics.ts)

## 2026-07-19 — Правило «генерация только по-русски» в технической части промпта
- Решение: запрет латиницы + легенда перевода технических полей (stddev → «разброс оценок внутри группы» и т.д.) в TECHNICAL_PROMPT, с исключением для ключей/enum JSON-схемы.
- Почему: в текст отчёта утекали имена полей (stddev = 0,17) и английские названия методик (5 Why, Ishikawa); техническая часть действует всегда, в отличие от редактируемой методической.
- Затронуто: backend/src/oc360/report/report.prompt.ts

## 2026-07-19 — Отчёт в статусе READY неизменяем
- Решение: блокировка генерации/сброса/правки блоков и в UI (disabled-кнопки с подсказкой, editable=false), и на сервере (отказ до обращения к LLM; переход READY→DRAFT разрешён).
- Почему: готовый к публикации отчёт нельзя менять случайно; только UI не защищает от гонки двух HR и устаревшей вкладки.
- Затронуто: backend/src/oc360/report/report.service.ts, frontend/app/hr-eval360/[cycleId]/ReportView.tsx

## 2026-07-17 — Удаление блоков отчёта через hiddenBlocks внутри sections
- Решение: удалённые HR блоки отчёта хранить списком ключей `hiddenBlocks` внутри JSON `sections`, а не отдельной таблицей/столбцом.
- Почему: без миграции БД; сбросы восстанавливают блоки автоматически (снимок хранит весь `sections`); поле едет существующими путями generate/update.
- Затронуто: backend/src/oc360/report/report.types.ts, frontend/lib/api.ts, frontend/components/eval360/Report360View.tsx

## 2026-07-17 — Два якоря сброса отчёта: initialSnapshot + preGenSnapshot
- Решение: два снимка в Cycle360Report — `initialSnapshot` (фиксируется один раз, до первой генерации) и `preGenSnapshot` (перед каждой генерацией); при откате снимки не обнуляются.
- Почему: HR нужен выбор «до всех генераций» / «на шаг назад»; неснимаемые якоря позволяют переключаться между ними до следующей генерации. Полная история версий отвергнута — шире скоуп без запроса.
- Затронуто: schema.prisma (2 nullable Json), report.service.ts (reset(mode)), ReportView.tsx (модалка с двумя действиями)

## 2026-07-17 — Таймауты генерации: LLM-клиент 300с, nginx /api 330с
- Решение: поднять таймаут запроса к LLM до 300с, а `proxy_read_timeout` nginx до 330с (строго больше backend).
- Почему: reasoning-модель MiniMax не укладывалась в 120с; прокси должен рвать соединение позже backend, иначе ошибка маскируется.
- Затронуто: llm.client.ts, nginx/nginx.conf, DEPLOY.md (в т.ч. напоминание про Traefik)

## 2026-07-17 — Пилотный LLM-провайдер: Gonka/OpenGNK, модель MiniMax-M2.7
- Решение: для автогенерации использовать proxy.gonka.gg (OpenAI-совместимый прокси децентрализованной сети Gonka), модель `MiniMaxAI/MiniMax-M2.7`.
- Почему: почти бесплатно (~$0.00015/1M токенов + 1M бесплатных), протокол 1-в-1 совпадает с нашим клиентом — подключение без правок кода; Kimi/GLM из доки фактически недоступны (404).
- Затронуто: только настройки /admin/llm (base URL https://api.proxy.gonka.gg/v1)

## 2026-07-16 — Отказ от OAuth-токена подписки Claude для автогенерации
- Решение: не использовать OAuth-токен подписки Pro/Max как источник LLM для портала; легальный путь — API-ключ (Console) + OpenAI-совместимый прокси (LiteLLM) либо иной провайдер.
- Почему: токен подписки предназначен для интерактивной личной работы — использование в приложении против условий; технически короткоживущий, не обновляется автоматически.
- Затронуто: архитектура подключения LLM (кода не потребовалось)

## 2026-07-16 — Настройки LLM в БД с приоритетом над env
- Решение: подключение к модели хранить в таблице `llm_settings` (правится в /admin/llm), env `LLM_*` — только fallback; ключ хранится открыто, наружу отдаётся маской (••••last4), пустой ввод не затирает сохранённый ключ.
- Почему: менять подключение без редеплоя; решение работает в закрытом контуре — риск хранения ключа в БД принят осознанно.
- Затронуто: schema.prisma (LlmSettings), src/settings/, oc360/report/llm.config.ts, frontend/app/admin/llm/

## 2026-07-16 — База знаний: полный текст документов в промпт (вариант A)
- Решение: активные документы базы знаний подставлять в system-промпт целиком (лимит 150 000 симв. с обрезкой), без эмбеддингов/векторного поиска; docx парсить через jszip (закреплён явной зависимостью — уже был транзитивной через exceljs).
- Почему: корпус — методички на единицы-десятки страниц, целиком влезают в контекст; эмбеддинги — лишняя инфраструктура без выигрыша на таком объёме.
- Затронуто: oc360/knowledge/ (docx.ts, knowledge.service.ts), report.prompt.ts (buildDocsBlock), вкладка «База знаний»

## 2026-07-13 — Двухслойный промпт отчёта и OpenAI-совместимый клиент на fetch
- Решение: system-промпт = редактируемая HR методическая часть (плейсхолдеры {{scale_min}}/{{scale_max}}/{{target_level}}) + защищённая техническая часть (строгая JSON-схема Report360Sections). LLM-клиент — нативный fetch к `/chat/completions` без новых зависимостей.
- Почему: HR настраивает методику, но не может сломать формат ответа (парсинг гарантирован normalizeSections); OpenAI-совместимость покрывает OpenAI/DeepSeek/vLLM/Ollama/прокси одной реализацией.
- Затронуто: oc360/report/ (report.prompt.ts, llm.client.ts, report.types.ts)
