## Классификация

| Префикс | Тип | Что описывает |
|---|---|---|
| BR | Бизнес-требование (Business Requirement) | Что бизнес хочет получить |
| UR | Пользовательское требование (User Requirement) | Что должен иметь возможность делать пользователь |
| FR | Функциональное требование (Functional Requirement) | Что должна делать система |
| NFR | Нефункциональное требование (Non-functional Requirement) | Производительность, безопасность, отказоустойчивость, масштабируемость, журналирование, интеграции, права доступа, ограничения качества |
| RULE | Бизнес-правило (Business Rule) | Правило обработки данных, ограничение или логика принятия решений, заданные заказчиком |
| CON | Ограничение (Constraint) | Технологическое, организационное или законодательное ограничение |

## FR-005 — Генерация по частям (1–8 запросов)
- **Тип:** Functional
- **Описание:** Система должна уметь разбивать генерацию отчёта на от 1 до 8 последовательных запросов (настройка пресета): каждой части — своя JSON-схема только её разделов и свой лимит вывода; при 6–7 частях по одной паре на запрос дробится сравнение по группам, при 8 — и сравнение с внешними группами; ответы частей система должна склеивать в один отчёт (разделы-пары — дописыванием), ошибка любой части — ошибка всей генерации, частичный отчёт не сохраняется.
- **Обоснование:** Потолок вывода задаёт шлюз провайдера и у разных шлюзов различается в разы (CON-002).
- **Источник:** DECISIONS 2026-07-21 (splitParts), 2026-07-27 (до 5, затем до 8 частей); задачи tasks/split-generation, tasks/split-generation-5
- **Приоритет:** Must Have
- **Реализует:** FR-001
- **Зависимости:** Нет
- **Связанные требования:** CON-002, CON-005
- **Статус:** Проверено
- **Реализация:** report.prompt.ts (partsForCount, ReportPart), report.service.ts (склейка), llm.config.ts (MAX_SPLIT_PARTS)
- **Проверка:** Смоуки составов n=1…8 и склейки; живые прогоны 2026-07-27…28 (отчёт собрался на 8 частях при потолке 4096)
- **Открытые вопросы:** Нет
- **Комментарий аналитика:** Нет

## RULE-001 — Зоны расхождения по |Δ|
- **Тип:** Business Rule
- **Описание:** Зона расхождения определяется по |Δ| (самооценка − оценка группы/окружения), округлённому до 0,1: |Δ| ≤ 0,3 — консенсус; 0,4–0,5 — зона внимания; |Δ| ≥ 0,6 — слепая зона (самооценка выше) или скрытый потенциал (самооценка ниже). Округление — по модулю с восстановлением знака.
- **Обоснование:** Методика компании (v1.2); симметрия границ для отрицательных Δ.
- **Источник:** DECISIONS 2026-07-20 (четвёртая зона); LESSONS 2026-07-20 (Math.round)
- **Приоритет:** Must Have
- **Реализует:** —
- **Зависимости:** Нет
- **Связанные требования:** FR-002, RULE-005
- **Статус:** Проверено
- **Реализация:** analytics.ts (zoneOfDelta — единственная точка правила)
- **Проверка:** Смоук с граничными случаями (±0,55)
