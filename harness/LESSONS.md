## 2026-07-20 — Reasoning-модель может сжечь весь max_tokens на <think> и не выдать JSON
- Что случилось: генерация падала с «Модель вернула только рассуждения без JSON» — модель потратила все 16000 токенов на размышления (заново анализировала данные), не начав ответ.
- Причина: длина размышлений случайна от запуска к запуску и растёт от строгих правил в промпте (после задачи №38 модель «думала» дольше); лимит 16000 упирался в потолок Gonka 16384.
- Урок: у reasoning-моделей бюджет вывода ставить в потолок провайдера и прямо указывать «рассуждай кратко, все решения уже приняты системой, сразу переходи к JSON»; лимит держать настраиваемым — потолки у провайдеров разные.

## 2026-07-20 — LLM нельзя доверять классификацию и арифметику даже на готовых числах
- Что случилось: в отчёте Седлецкого модель положила скрытые возможности (Δ до −2,9) в «Слепые зоны», пропустила компетенции в разборах пар, не включила лучшую компетенцию (окружение 4,25) в сильные стороны и написала «3,17 ниже 3,0» — при том, что все числа ей передавались готовыми и верными.
- Причина: модель выполняла классификацию/отбор сама по текстовым правилам промпта и ошибалась в знаке Δ и критериях.
- Урок: всё детерминированное (пороги, знаки, сортировки, составы списков) считать кодом и передавать готовыми метками; модели оставлять только интерпретационный текст; проверять её выводы против собственных цифр отчёта.

## 2026-07-19 — Ошибка гидрации Next.js из-за localStorage в первом рендере
- Что случилось: «Text content does not match server-rendered HTML» при открытии портала — сервер и клиент рендерили разные меню Sidebar.
- Причина: AuthContext читал localStorage (сохранённая роль) в инициализаторе useState — на сервере localStorage нет, на клиенте роль другая.
- Урок: браузерное состояние (localStorage/время/random) применять только в useEffect после монтирования; предупреждение в консоли («Prop d did not match» + стек) точно указывает компонент-виновник.

## 2026-07-19 — Границы категорий держать в одном месте
- Что случилось: порог слепой зоны 0,6 в таблице (строгое >) и в промпте («0,6 и более») разошёлся — разрыв ровно 0,60 классифицировался по-разному в таблице и в тексте ИИ.
- Причина: одно и то же правило методики закодировано в двух местах разными сравнениями.
- Урок: пороговые сравнения считать на округлённых значениях и нестрого (>=); формулировки промпта сверять с кодом при каждой правке порогов.

## 2026-07-17 — Reasoning-модель кладёт <think> прямо в content
- Что случилось: генерация падала «в ответе нет JSON» — ответ MiniMax начинался с `<think>…</think>`, а внутри рассуждений были фигурные скобки, ломавшие разбор «от первой { до последней }».
- Причина: reasoning-модели вкладывают рассуждения в `content` (или в отдельное поле `reasoning_content`); наш парсер этого не ожидал.
- Урок: перед извлечением JSON срезать `<think>…</think>` (и висячий незакрытый `<think>`); проверять `reasoning_content` как запасной источник; ставить явный `max_tokens`, чтобы рассуждения не съедали бюджет ответа.

## 2026-07-17 — PowerShell ломает UTF-8 кириллицу в теле запроса
- Что случилось: при ручной проверке API через `Invoke-RestMethod` в модель ушли «?????» вместо русского текста — модель отвечала не на тот вопрос и по-китайски.
- Причина: PowerShell по умолчанию отправляет тело не в UTF-8.
- Урок: для проверок API с русским текстом PowerShell не годится без явной кодировки; к диагностике структуры ответа это не мешает, но к качеству ответа — да.

## 2026-07-17 — Таймаут reverse-proxy должен быть больше таймаута backend→LLM
- Что случилось: генерация обрывалась «таймаут запроса», хотя модель ещё работала.
- Причина: сначала мал был таймаут LLM-клиента (120с), при подъёме — nginx (180с) резал бы раньше backend (300с).
- Урок: таймауты в цепочке браузер→nginx→backend→LLM поднимать согласованно; прокси всегда с запасом больше backend (у нас 330с против 300с).

## 2026-07-16 — Список моделей провайдера брать только из GET /v1/models
- Что случилось: `moonshotai/Kimi-K2.6` из документации Gonka дал 404 model_not_found; реально сервер отдавал одну `MiniMaxAI/MiniMax-M2.7`.
- Причина: документация описывает «что бывает», ноды обслуживают «что есть сейчас».
- Урок: перед настройкой модели дёрнуть `GET {base}/v1/models` — единственный источник правды.

## 2026-07-16 — Правка schema.prisma = всегда ПАРА: generate + db push
- Что случилось: дважды ловили ошибки по отдельности — TS2339 «Property 'llmSettings' does not exist on PrismaService» и «The table … does not exist in the current database».
- Причина: `prisma generate` обновляет только типы клиента, `prisma db push` — только структуру БД; по одной команде получается половина результата.
- Урок: после любого изменения схемы выполнять обе: `node_modules\.bin\prisma generate` и `node_modules\.bin\prisma db push`, затем перезапуск backend.

## 2026-07-16 — Глобальный npx prisma тянет Prisma 7 и падает
- Что случилось: `npx prisma …` завершался ошибкой P1012 на валидной схеме.
- Причина: глобальный npx ставит свежую Prisma 7, проект — на Prisma 6.
- Урок: только локальный бинарник `node_modules/.bin/prisma` (Windows: `node_modules\.bin\prisma`).

## 2026-07-15 — git pull падает на изменённом package-lock.json
- Что случилось: `git pull origin mvp2` отказывался: «Your local changes to backend/package-lock.json would be overwritten».
- Причина: локальная сборка меняет lockfile, изменения не закоммичены.
- Урок: `git checkout -- backend/package-lock.json`, затем pull; lockfile локально не править.
